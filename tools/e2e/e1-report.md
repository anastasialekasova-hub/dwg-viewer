## 4.2.14 — инкогнито

Основной путь (выдать доступ в инкогнито и открыть ссылку в окне инкогнито) — харнесс зависает после выдачи доступа
(2 из 2 в прошлом запуске: `STEP-END rc=signal SIGTERM s=1800 :: tools/e2e/e1/cookies.js`).

Запасной путь проверен прогоном c (`tools/e2e/out/pull-c/e1/incognito.json`): OTR-контекст puppeteer, расширению инкогнито
не разрешено (`allowedIncognito:false`, ключа `incognito` в манифесте нет — по умолчанию `spanning`). В обычном контексте
ссылка ушла во вьюер (`viewerTabs:1`, сервер файла не тронут — качает вьюер); в OTR-контексте вкладок вьюера 0, страница
осталась на месте, файл скачался (`completed`, 1 081 979 байт = исходнику), этот файл с диска открылся во вьюере:
`plan.dwg · Model`, «162 of 164 objects drawn». Оговорка: это OTR-контекст, а не настоящее окно инкогнито; настоящим вводом —
у product-reviewer. Вариант для Э2: `"incognito": "not_allowed"`, чтобы поведение не зависело от галочки.
